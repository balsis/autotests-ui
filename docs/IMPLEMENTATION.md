# Особенности реализации

## Покрытые потоки

| Область | Сценарии |
|---|---|
| Авторизация | Ошибочные данные, успешный вход, переход к регистрации. |
| Регистрация | Регистрация пользователя из `TEST_USER`. |
| Дашборд | Navbar, sidebar, тулбар, 4 графика. |
| Курсы | Пустой список, создание с PNG, редактирование. |

Все сценарии имеют `regression`; также применяются маркеры `authorization`, `registration`, `dashboard`, `courses`.

## Соглашения

- Селектор — значение `data-testid`; коллекции используют `nth` или `str.format(**kwargs)`.
- Тесты описывают бизнес-действия. Селекторы и повторяемые шаги размещаются ниже по слоям.
- Для защищённых страниц использовать `page_with_state`, а не повторный вход в каждом сценарии.
- Не использовать `sleep`; ожидания выполняются через Playwright `expect`.

## Ограничения и долг

| Приоритет | Факт |
|---|---|
| Высокий | `environment.properties` содержит `settings.model_dump()`, включая пароль `TEST_USER`; Allure results нельзя публиковать без исправления. |
| Высокий | Регистрация и созданные курсы не очищаются, при этом CI использует 2 воркера. Повторы зависят от состояния LMS. |
| Средний | `FileInput.set_input_files()` не регистрирует UI coverage. |
| Средний | `Input.get_raw_locator()` игнорирует `nth` при построении XPath для покрытия. |
| Средний | Тест дашборда ожидает литерал `"username"`, а не значение из настроек. |
| Низкий | Локальные изменения `scripts/playwright_authorization.py` и `scripts/playwright_keyboard.py` дают `IndentationError`; pytest их не импортирует. |

Проверено 6 ноября 2026: основной код компилируется, `pytest --collect-only -q -n 0` собирает 10 тестов. Прогон против LMS не выполнялся.
